# LensQuery — conventions for agents and contributors

LensQuery is a Rust CLI that OCRs images and makes the text inside them
searchable offline, backed by a single SQLite FTS5 database. One binary, no
server, no network.

Read before changing code:

1. [docs/api-contracts.md](docs/api-contracts.md) — the public surface of each
   module. Changing anything in there is a breaking change and needs its own PR.
2. [docs/decisions/](docs/decisions/) — why the design is the way it is. If you
   are about to argue with a design choice, the argument is probably already in
   there with the counter-evidence.
3. [docs/benchmarks.md](docs/benchmarks.md) — the measurements behind the
   defaults. Do not change a default because it seems better; change it because
   this file, or a new run of the probes in `examples/`, says it is.

## Commands

Everything goes through the `justfile` (`just --list` for the full set):

| Command | What it does |
| --- | --- |
| `just check` | `lint` + `test` + `privacy`. This is CI. Run it before you push. |
| `just test` | `cargo test` — unit tests *and* the `lq serve` integration tests. |
| `just lint` | `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings`. |
| `just recall` | OCR the committed fixtures and assert the text comes back. Needs a real libtesseract. |
| `just doctor` | What a user sees when their install is broken. |
| `just package` | Dry-run what would go to crates.io. |

`just test` is deliberately **not** `cargo test --lib`. The integration tests in
`tests/` drive the real binary over stdin and are the only thing that catches a
regression in the `lq serve` line protocol.

## Hard rules

Ordered by how badly breaking them hurts.

- **No auto-commit.** Never run `git commit` or `git push` unless asked for a
  commit in that specific turn. Finishing a task does not imply permission to
  commit. Leave changes in the working tree.
- **Nothing private gets committed.** No real corpora, no screenshots, no
  absolute paths from anyone's machine, no `.traineddata`, no database files.
  `just privacy` ([scripts/check-privacy.sh](scripts/check-privacy.sh)) enforces
  this and is part of `just check`. Test images are synthetic and generated by
  [scripts/make_fixtures.py](scripts/make_fixtures.py).
- **`osd` is not a language.** It is an orientation-and-script-detection model
  and it must never appear in the Tesseract `lang=` string. Putting it there
  makes `Init3` fail on machines that lack it and changes nothing on machines
  that have it.
- **All user input goes through `db::build_fts5_query` before it reaches
  `MATCH`.** No exceptions, no "this one is already safe." FTS5 query syntax has
  operators in it; a bare user string is both an injection surface and a source
  of confusing syntax errors.
- **The OCR result has three states and they never collapse.** `Ocr::Text(s)` is
  text we read, `Ocr::Empty` is an image we read successfully that contains no
  text, `Ocr::Failed` is an image we could not process. "Empty" is a fact about
  the image and stays in the index; "failed" is a fact about the run and gets
  retried. Mapping either to the other loses that distinction permanently.
- **WAL is set on every `db::connect()`**, not once at creation. A database
  opened by an older build, copied from elsewhere, or restored from a backup
  otherwise runs in rollback-journal mode and blocks readers during indexing.
- **`models.rs` fields are a contract.** Adding a field is fine. Renaming or
  removing one breaks anything reading the index, including older binaries.
- **The FTS5 content column is index 1, not 0.** Column 0 is the `UNINDEXED`
  `file_id`. Off-by-one here does not error — it silently searches or snippets
  the wrong column.
- **`snippet()` takes the FTS5 table by name**, not whatever alias the
  surrounding query gave it. Passing the alias is a runtime SQLite error, and
  only on the code path that asks for a snippet.
- **OCR workers hold a thread-local `TessBaseAPI`.** Creating one per image
  costs more than the OCR does. Do not move engine construction into the
  per-image path, and do not share one engine across threads.
- **`init_process_env()` runs from `main`, before any thread is spawned.** It
  sets `OMP_THREAD_LIMIT`; `setenv` concurrent with any other thread is a data
  race, not a lint.
- **The release profile is `panic = "unwind"`.** [`indexer`] wraps each image in
  `catch_unwind` so one bad file cannot kill an hour-long index run.
  `panic = "abort"` makes that inert. Do not "optimize" it.

## Style

`cargo fmt` and `clippy -D warnings` are the style guide; there is no second
document. Beyond that:

- Prefer an `#[expect(lint, reason = "...")]` with a real reason over `#[allow]`,
  and prefer fixing it over either. Note that `-D warnings` implies
  `-D unfulfilled-lint-expectations`, so an `#[expect]` that turns out to be
  unnecessary is itself an error — which is the point.
- Comments explain *why*, and specifically why the non-obvious choice was made.
  Do not narrate what the next line does. Do not delete a comment because it is
  long; delete it because what it says is now obvious from the code.
- A measured number in a comment needs a pointer to where it was measured
  ([docs/benchmarks.md](docs/benchmarks.md) or an ADR). A bare number with no
  provenance is worse than no number.
- Public items get a doc comment. Modules get a header saying what the module is
  for, not what it contains.

## Decisions

Anything that will be argued about again — a default, a dependency, a schema
choice, a platform workaround — goes in `docs/decisions/NNNN-slug.md` with
Context / Decision / Consequences / Reconsider-when. Numbers are sequential and
never reused. An ADR that turns out to be wrong gets superseded, not deleted;
the wrong turn is the useful part.
